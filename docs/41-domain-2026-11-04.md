## What Vercel shows

- **The domain:** thealchemistdetailing.com, team Wiffy Washes. Bought Nov 4, 2026; paid until Nov 4, 2027; auto-renew on. It uses Vercel's own nameservers, so the address records needed no hand setup.
- **The live project (`alchemist-detailing`):**
  - thealchemistdetailing.com is the production address.
  - www.thealchemistdetailing.com forwards to it with a permanent (308) redirect, a project-domain setting.
  - Vercel's configuration check reports neither address as misconfigured.
  - Certificates for both were issued on Nov 4 and renew automatically.
- **The database the address uses:** `config.js` sends every address except the test one (`alchemist-detailing-test.…`, or `?project=test`) to the live Supabase project, so the new address takes real bookings with no change. Supabase's API accepts any origin, and the `admin-create-team-account` function answers any origin. Guest booking and text codes need no Supabase change for a new address.

## What changed in the code

- **`site/index.html`:** the seven address lines now say https://thealchemistdetailing.com/:
  - the canonical link;
  - `og:url`, `og:image` and `twitter:image`;
  - the LD+JSON `url`, `image` and `logo`.
- **`site/sitemap.xml`:** the new address; `lastmod` 2026-11-04.
- **`site/robots.txt`:** the sitemap line uses the new address.
- **`site/vercel.json`:** one permanent redirect, used only when the host is `alchemist-detailing.vercel.app`. It sends that host to `https://thealchemistdetailing.com/:path*`. This follows Vercel's documented pattern for a project's vercel.app address. Query strings pass through, and the browser keeps the `#page` part.
  - Not affected: the test site, preview deployments and each deployment's own URL, because their hosts don't match.
  - Why a code rule: the Vercel tools here can't edit an existing project domain's setting.
